# TSB 0.1 无感听写与记忆助手设计

日期：2026-08-05

状态：已批准，作为 0.1 执行基线

## 1. 产品定位

TSB 0.1 是一款常驻 macOS 的轻量个人 Assistant。它通过一次低成本操作接收用户的自然语音，完成稳定转录、个性化整理与总结，并把可追溯的项目状态和记忆安全保存在本地，使用户下次启动时能够继续上次的项目，而不是重新解释背景。

0.1 不以“功能很多”或“多个 Agent 协作”为目标，只验证以下核心闭环：

> 听写 → 稳定转录 → 个性化总结 → 记忆落地 → 下次恢复

## 2. 0.1 范围

### 2.1 必须完成

- 以 OpenDictation 为 macOS 客户端基座，保留全局快捷键、录音状态和轻量结果界面。
- 支持自然中文、中英文混合、停顿、口头语和自我纠正的听写。
- 产生临时转录、稳定转录和语义修正后的整理文本。
- 输出摘要、关键事实、决定、想法、待办候选和不确定信息。
- 待办只能作为候选，不因一句模糊表达自动创建任务。
- 使用一个国产主模型 API 完成语义修正、总结和结构化提取。
- 使用一个 SecondBrain Agent 负责理解当前目标并产生结构化结果。
- 使用确定性的 SessionOrchestrator 管理状态、重试、取消、幂等和恢复。
- 在本地保存会话事件、转录、总结、项目状态、用户模型、记忆和来源。
- 下次启动时恢复精简用户模型、当前项目状态、上次检查点和相关记忆。
- 允许用户查看、纠正和删除记录；纠正必须回写项目状态和记忆。
- 稳定转录成功后默认删除原始音频；失败音频保留 24 小时；重要音频可由用户手动永久保留。
- 文件能力仅限应用自己的数据目录和用户明确授权的落地目录。

### 2.2 明确不做

- 完整语音回复和流式 TTS。
- Barge-in 和持续语音对话。
- 多 Agent 协作。
- 自动操作第三方应用。
- 扫描或整理用户整个电脑。
- 复杂知识图谱和全库关系探索。
- 无需确认的任务执行。
- 一直后台监听。

这些能力属于后续阶段，0.1 只保证底层接口和数据结构不会阻碍未来扩展。

## 3. 系统结构

0.1 采用“一个 Agent 大脑 + 确定性运行内核”的结构。

```text
用户语音
  ↓
AudioCapture + VAD
  ↓
本地国产 ASR Provider
  ↓
稳定转录
  ↓
SecondBrain Agent（国产主模型 API）
  ↓
结构化结果：修正文本、摘要、事实、决定、想法、待办候选
  ↓
SessionOrchestrator
  ↓
EventStore + ProjectState + UserModel + MemoryStore
  ↓
结果卡片与下次恢复检查点
```

### 3.1 SecondBrain Agent

0.1 只有一个 Agent。它负责理解稳定转录，结合当前项目状态和相关记忆，输出结构化结果。它不直接写文件或管理重试，也不拥有系统状态。

### 3.2 SessionOrchestrator

SessionOrchestrator 是确定性代码，不是小模型。它负责：

- 当前录音和处理状态；
- 请求 ID、幂等和重复提交保护；
- API 超时、重试和取消；
- 数据写入顺序和事务；
- 应用异常退出后的恢复；
- 音频生命周期和清理；
- 权限检查。

### 3.3 Provider 边界

ASR 和主模型通过稳定接口接入，业务层不依赖具体厂商：

- `ASRProvider`：接收音频，返回临时和稳定转录；
- `ReasoningProvider`：接收受控上下文，返回结构化 Assistant 结果；
- `EmbeddingProvider`：在本地生成检索向量；

0.1 不创建 TTS 接口或调用。第三阶段增加语音输出时，应复用同一套事件、取消、权限和 Provider 设计原则，而不是改动现有记忆数据流。

## 4. 记忆与连续项目状态

“今天聊完明天不能忘”不能只依赖向量检索。0.1 使用四层本地状态：

1. `EventStore`：追加保存发生过的语音会话、纠正、模型结果和状态变化。
2. `ProjectState`：保存目标、阶段、决定、未解决问题、下一步、约束和来源。
3. `UserModel`：保存用户明确表达的长期偏好、稳定事实、常用术语、权限边界及来源。
4. `MemoryStore`：保存可检索的情景记忆和语义记忆。

完整历史不直接进入每次模型调用。Context Builder 按固定预算组装：

- 系统规则和权限；
- 精简用户模型；
- 当前项目状态；
- 最近会话；
- 与当前输入相关的少量记忆证据。

常规上下文目标为 6,000–15,000 Token。项目和记忆增长时，通过精简状态、增量更新和按需检索保持该预算，不让上下文随历史线性增长。

0.1 的关系建立只做低成本增量关联：同一项目、同一人物、相同术语、时间连续和明确引用。复杂的因果、冲突和跨文件主动探索延后到第二阶段。

## 5. 个性化 Assistant 输出

主模型不是输出固定模板，而是在用户允许的范围内利用以下信息进行个性化整理：

- 用户常用名称和术语；
- 当前项目阶段；
- 用户偏好的总结长度和表达方式；
- 之前确认的事实和决定；
- 用户对历史输出的纠正记录。

每项写入长期记忆的内容必须保留来源、时间和置信度。模型推断与用户明确陈述分开保存；低置信度推断不能自动成为稳定用户事实。

## 6. API 使用边界

默认部署采用混合架构：

- 本地：录音、VAD、ASR、Embedding、SQLite、文件和检索；
- 外部：一个国产主模型 API；
- 可选：国产云端 ASR 只作为用户主动启用的降级或对照方案。

因此正常的“听写 + 总结”流程只依赖一个外部模型 API。模型候选通过 TSB 自有测试集比较，重点测试中文语义修正、结构化输出、记忆一致性、工具调用稳定性、速度和成本。具体厂商通过 Provider 配置切换，不写死在业务逻辑中。

## 7. 音频与本地存储策略

音频生命周期：

```text
录音产生临时文件
→ 完成稳定转录
→ 事务写入转录、总结、记忆和来源
→ 验证写入成功
→ 默认删除原始音频
```

异常规则：

- ASR 失败、中断或结果未持久化：音频保留 24 小时；
- 用户标记重要：永久保留，直到用户主动删除；
- 失败音频缓存总量设硬上限，默认 2GB；
- 日志和模型缓存分别设置容量和清理策略；
- 删除记忆时同步删除向量、关系和派生索引。

## 8. 本地资源目标

0.1 优先支持 Apple Silicon，推荐 16GB 统一内存：

- 空闲新增内存目标：0.2–0.5GB；
- 录音和轻量 ASR：约 1.5–3GB；
- 0.6–0.8B ASR 活跃时：约 2–4GB；
- ASR 与索引并行峰值目标：不超过 6GB 新增占用；
- 首次安装磁盘目标：3–8GB，取决于 ASR 模型。

8GB 机器使用轻量本地 ASR 和云端主模型，并在空闲后卸载模型；更重的 ASR 作为高配置选项。上述数字是工程预算，模型选定后必须在目标 Mac 上实测冷启动、实时因子、内存峰值、温度和电池消耗。

## 9. 错误处理与恢复

- ASR 失败：保留音频和会话状态，允许后台重试或用户重新处理。
- 主模型 API 失败：稳定转录仍然保存；总结任务进入可恢复队列。
- 结构化输出无效：不写入长期记忆，使用同一请求 ID 重试或降级为纯文本摘要。
- 数据写入失败：不删除音频，不宣布记录完成。
- 应用退出：下次启动从最后一个持久化检查点继续。
- 用户纠正：追加纠正事件，不直接覆盖来源；更新 ProjectState，并降低旧记忆权重。
- 删除请求：删除原始记录、派生摘要、向量和关系，同时保留最小删除审计信息。

## 10. 0.1 验收标准

0.1 只有同时满足以下条件才算完成：

1. 用户能通过低成本入口开始和结束听写。
2. 可以显示临时转录，并产生稳定转录和修正文本。
3. 中文、中英文混合、专有名词和自我纠正进入真实测试集。
4. 一个国产主模型 API 能稳定返回结构化总结。
5. 用户纠正后的事实在下一次启动中正确恢复。
6. 关闭或异常退出应用后，项目状态不会丢失。
7. 稳定写入成功后原始音频按策略删除；失败音频可恢复并在 24 小时后清理。
8. 正常记录模式只依赖一个外部模型 API。
9. 不存在多 Agent、TTS 调用、第三方自动操作或全盘文件扫描。
10. 16GB Apple Silicon 机器上的内存、延迟和磁盘占用满足资源预算或有明确降级策略。

## 11. 后续阶段接口

- 第二阶段：混合检索、增量关系图、冲突发现和记忆整理。
- 第三阶段：流式 TTS、Barge-in 和完整语音对话。
- 第四阶段：受控文件读取、外部工具、审批、回滚和必要的专业子 Agent。

后续能力必须复用 0.1 的事件、项目状态、用户模型、权限和 Provider 边界，不重新建立一套割裂的数据链路。
