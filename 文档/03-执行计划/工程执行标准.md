# TSB 工程执行标准

版本：1.0

生效日期：2026-08-06

## 1. 标准的含义

TSB 所采用的“大厂标准”不是增加会议、表格和层级，而是确保每项变更都可追踪、可测试、可回滚、可审计。速度重要，但不能用用户数据安全、状态一致性和长期可维护性换取短期速度。

## 2. 单一事实来源

- 产品范围以 `文档/01-产品定义` 中已批准的规格为准。
- 实施顺序以 `文档/03-执行计划` 中当前有效计划为准。
- 重大技术选择必须记录在 `文档/04-决策记录`。
- 发布结论必须由 `文档/05-测试与验收` 中的证据支持。
- 需求、设计、代码和测试发生冲突时停止发布，先修正文档或实现，不允许口头豁免。

## 3. 版本控制和分支

- 默认分支为 `main`，必须始终可构建。
- 功能分支使用 `codex/<scope>` 或 `feature/<scope>`；修复使用 `fix/<scope>`。
- 每个提交只表达一个可独立说明的意图，提交信息使用 `type(scope): summary`。
- 禁止提交 API Key、用户音频、真实转录、运行数据库和下载模型。
- 参考项目与正式产品代码隔离；正式代码不得长期开发在 `example` 中。
- 合并前必须完成代码审查和自动化质量门禁。

## 4. 设计和变更控制

- 新能力先有设计规格，规格明确范围、非目标、数据流、异常路径和验收标准。
- 架构或数据模型的不可逆变化使用 ADR 记录背景、选项、决定和后果。
- 不提前为后续阶段实现抽象；只有存在第二个真实实现时才提取通用层。
- API、数据库和持久化格式必须带版本；迁移必须可重复执行并支持失败恢复。
- 任何删除数据的流程必须先验证派生数据已经事务性落盘。

## 5. 开发方法

- 默认采用测试驱动：先写失败测试，再写最小实现，再重构。
- 每个任务产生一个可独立测试、可独立审查的交付物。
- Swift 并发代码必须明确 Actor 边界；UI 状态只在 `MainActor` 更新。
- 状态变化通过显式事件完成，不允许多个组件分别写同一份会话状态。
- API 调用必须有请求 ID、超时、取消、有限重试和幂等策略。
- 错误不能静默吞掉；用户可恢复的错误必须给出恢复入口。

## 6. 自动化质量门禁

每个合并请求必须依次通过：

1. XcodeGen 配置生成成功；
2. Debug 构建成功；
3. 单元测试全部通过；
4. 持久化和恢复集成测试通过；
5. SwiftLint 无新增错误；
6. `git diff --check` 无格式错误；
7. 仓库秘密扫描无命中；
8. 不包含真实用户数据、音频或数据库；
9. 对应验收矩阵有证据或明确标记为尚未进入发布门禁。

发布候选还必须通过真实 Apple Silicon 机器上的端到端、资源和隐私测试。

## 7. 测试分层

- 单元测试：状态转换、Context Builder、结构化解析、记忆合并和清理规则。
- 契约测试：ASR Provider、Reasoning Provider、持久化接口和错误映射。
- 集成测试：录音结束到稳定落盘、API 失败恢复、应用重启恢复、音频清理。
- 端到端测试：快捷键启动、转录、总结、纠正、删除和次日恢复。
- 性能测试：首段转录延迟、稳定转录延迟、总结延迟、内存峰值、磁盘增长和耗电。
- 回归测试：每个已修复缺陷必须留下能复现旧问题的自动化测试。

## 8. 隐私和安全

- API Key 只存入 macOS Keychain。
- 日志默认不记录音频、完整转录、Prompt、用户模型正文和 API Key。
- 网络请求只发送完成当前任务所需的最小上下文。
- 稳定结果事务写入成功前不得删除音频。
- 成功音频默认删除；失败音频保留 24 小时且缓存总量不超过 2GB。
- 用户删除记录时同步删除摘要、向量、关系和派生索引。
- 所有外部模型 Provider 必须可关闭和替换。

## 9. 可观测性

每个处理会话生成本地 `sessionID` 和每次模型调用的 `requestID`。只记录以下非敏感指标：

- 阶段开始、结束和耗时；
- 状态转换；
- 模型与版本标识；
- 成功、取消、超时和错误类型；
- 输入音频时长和输出字符数，不记录内容；
- 内存峰值和临时文件大小。

## 10. Definition of Done

任务只有满足以下全部条件才可标记完成：

- 实现与已批准规格一致；
- 正常路径和关键失败路径有自动化测试；
- 测试在干净环境通过；
- 没有未解释的警告、占位符或禁用测试；
- 数据迁移和删除行为经过验证；
- 日志不泄露用户内容；
- 资源占用没有超过既定预算，或已有明确降级策略；
- 文档、ADR 和验收证据已同步更新；
- 变更可以通过回退提交恢复；
- 审查者能够仅凭提交和文档理解变更原因。

## 11. 发布门禁

0.1 发布采用 `0.1.0-rc.N` 候选版本。连续三轮核心端到端测试无阻断缺陷、无数据丢失、无音频生命周期违规后，才可标记 `0.1.0`。

以下情况直接阻断发布：

- 用户确认过的记忆在重启后丢失；
- 数据未落盘就删除音频；
- 重复调用导致重复记忆或重复文件；
- 日志或仓库包含用户内容、音频或密钥；
- 应用无法在支持的最低 macOS 版本启动；
- 任何 P0/P1 缺陷未关闭。
