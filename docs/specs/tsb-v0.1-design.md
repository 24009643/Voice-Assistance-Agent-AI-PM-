# TSB 0.1 快捷听写设计

日期：2026-08-05

最后更新：2026-08-18

状态：最终范围已收敛，等待用户确认后进入实施计划

## 1. 产品目标

TSB 的核心价值是抓住用户正在形成的灵感，而不是把一次听写包装成复杂的 Assistant。

TSB 0.1 是一个运行在 macOS 上的本地优先听写工具。用户通过全局快捷键开始说话，应用在 Mac 顶部刘海区域即时反馈，把语音转成可追溯的原始文本，在不改变原意的前提下做最小本地清理，并将结果自动复制到剪贴板。

0.1 只验证一条核心闭环：

> 快捷键开始 → 稳定录音 → 本地分段转录 → 本地最小清理 → 保存原文 → 自动复制 → 随处粘贴

产品是否成功，首先取决于“准、快、不丢、不中断下一次灵感”。生成式 LLM、语音唤醒、光标直接插入和知识库均不能阻塞这条链路。

## 2. 已确认的验证条件

- 首台目标设备：M5 Pro、48GB 内存的 MacBook。
- 0.1 主要由产品发起人本人深度验证，可邀请少量外部用户提供参考，但不做公开分发。
- 典型单次口述为 3–5 分钟；必须支持 10 分钟口述。
- 10 分钟作为 0.1 单次录音上限：9 分 30 秒提示，10 分钟自动结束并继续转录，不丢弃已录音频。
- 普通话、粤语和中英混合会随机出现；产品不要求用户预先选择语言。
- 音频始终留在本地。0.1 不把任何听写文本发送给 LLM。
- 签名、安装器、自动模型下载、完整新手引导和公开隐私说明后移到 0.2。

上述硬件是性能基线，不代表未来最低配置。0.1 先证明体验成立，0.2 再在更低配置 Mac 上测量和收窄兼容范围。

## 3. 第一性原理与不可破坏守则

1. **交付结果优先**：完成条件是用户及时得到一段可以直接粘贴的文字，不是某个模型或动画运行成功。
2. **原意优先**：不确定是否该删的内容一律保留，不为了文笔流畅而重写用户表达。
3. **来源不可覆盖**：原始转录和本地清理文本分开保存；后者不能覆盖前者。
4. **本地闭环完整**：录音、VAD、ASR、清理、保存和复制全部不依赖网络。
5. **新灵感不等待旧任务**：上一条仍在处理时，用户仍能开始下一次录音。
6. **一次交付**：同一会话最多自动写入一次剪贴板；重复事件和迟到回调不能重复交付。
7. **空闲不监听**：0.1 空闲时不占用麦克风，不实现任何形式的语音唤醒。
8. **没有假按钮**：没有实际行为的未来功能不出现在主界面。唯一例外是完整可保存、取消和删除的 API 预配置页，它必须清楚说明 0.1 不会调用。
9. **真实口述验证**：模型宣传不等于产品效果，每轮修改都使用用户自己的语料回归。

## 4. 0.1 范围

### 4.1 必须完成

- 原生 Swift/macOS 应用，常驻菜单栏并以刘海区域作为主要反馈入口。
- 以 [OpenDictation](https://github.com/kdcokenny/OpenDictation) 为客户端壳层参考，遵守 MIT License 和归因要求。
- 支持两种可配置的快捷键方式：
  - 按一次开始、再按一次结束；
  - 按住说话、松开结束。
- `Escape` 取消本次听写；取消后不保存成功记录、不复制，并删除临时音频。
- 本地采集 16kHz、单声道 PCM，同时写入临时 WAV 并提供录音电平。
- 通过 VAD 按自然停顿切段，将已完成段落交给 SenseVoiceSmall。
- 使用 sherpa-onnx 接入固定版本的 SenseVoiceSmall int8 模型。
- 自动处理普通话、粤语和中英混合，不提供手动语言切换。
- 刘海中逐段追加稳定转录，不做反复跳字的逐 Token 字幕。
- 用户结束录音后生成最终原始转录和本地清理文本。
- 清理只处理确定性空白、重复标点和可安全判断的独立填充音；任何不确定内容保留。
- 原始转录始终可查看；修改位置以颜色和删除线或下划线区分。
- 默认自动复制本地清理文本，并提供“复制原文”和“复制本地结果”。
- 本地保留最近听写记录；原始转录默认保留 7 天，可选择 1 天、7 天、30 天或永久。
- 成功保存文本后删除音频；失败音频最多保留 24 小时供重试。
- 自行设计 TSB 的刘海内容、状态层级和设置页；只复用 OpenDictation 成熟的窗口与系统能力。
- 提供“0.2 AI 连接预配置”设置页，包含 Provider、模型、HTTPS Base URL 和 API Key。
- API 配置支持保存、取消未保存编辑和删除；Key 只进入 macOS Keychain，保存后不回填明文。
- API 配置页明确显示：“0.1 仅保存配置，不测试连接、不发送文本、不产生模型费用。”

### 4.2 明确不做

- 生成式 LLM 调用、文本分层、总结、重组或语义改写。
- API 连接测试和 Provider 合同测试。
- 通过词、语气词、长音或停顿自动唤醒应用。
- 常驻麦克风、持续后台监听和无感激活。
- 真正逐 Token 的流式 ASR；0.1 使用 VAD 分段准实时展示。
- 默认在当前光标位置直接插入文字。
- 云端 ASR 和音频上传。
- 云端同步、账户、计费、公共 API Key 和服务端代理。
- 想法拆解、待办生成、知识库、长期记忆和 Agent。
- 语音回复、TTS、Barge-in 和持续语音对话。
- 无法点击的未来功能按钮或“敬请期待”操作入口。
- Windows、iOS、安装签名、安装器和公开分发流程。

后续能力只写入路线图，不在 0.1 预建空接口、抽象层或不可用 UI。

## 5. 为什么保留 VAD、分段预览和输入限制

### 5.1 真正流式输出

真正流式 ASR 会在用户说话时不断修改尚未稳定的字词。SenseVoiceSmall 在本方案中按离线段落识别，不把它包装成原生流式模型。0.1 只要求：

- 波形即时响应；
- 检测到自然停顿后识别刚完成的段落；
- 完成段落只追加一次；
- 结束录音时只补齐尾段。

这样比逐字跳动更稳定，也显著小于真正流式解码的工程量。

### 5.2 3–10 分钟口述对 VAD 的影响

如果等 3–10 分钟录音全部结束后才开始识别，会同时带来最终等待过长、单次失败损失过大、恢复困难和长音频占用增加。VAD 的意义不是炫技，而是把长口述拆成已经完成的小段，在录音期间逐步完成大部分 ASR。

VAD 只负责找语音边界，不删除内容。停顿阈值、最短段长和最长段长是少数需要真机校准的参数；长停顿不等于录音结束。

### 5.3 语言随机出现的影响

- 不让用户选择语言；每个完成段由 SenseVoice 自动判断。
- 段落必须按采集顺序组装，不能按检测语言分组。
- 同一段内中英切换时不得强制翻译或统一语言。
- Golden Set 分层统计三类场景，不能用总体平均分掩盖粤语或中英混合退化。

### 5.4 LLM 输入限制的影响

0.1 不调用 LLM，因此没有运行时 LLM Token 或输入长度问题。0.1 只需保留按顺序排列的转录段和最终本地文本。

0.2 加入“想法分层”时，3–5 分钟与 10 分钟文本会直接影响最大输入、输出上限、费用、超时和是否需要按段处理。这些规则必须在真实 0.1 文本长度分布出现后再定，不能现在猜一个通用限制。

## 6. 核心数据流

```text
Global Hotkey
  ↓
Session Coordinator
  ↓
Audio Capture ──→ Temporary WAV for recovery
  ↓ PCM frames
VAD Segmenter
  ↓ completed speech segment
SenseVoiceSmall via sherpa-onnx
  ↓ stable segment transcript
Transcript Assembler
  ↓ originalText
Conservative Cleaner
  ↓ localCleanedText + editOperations
Atomic Local Save
  ↓
Single Clipboard Delivery + Result UI
```

API 预配置与上述运行链路完全隔离：

```text
Settings Draft
  ├─ Cancel → discard draft
  ├─ Save   → non-secret settings + Keychain credential
  └─ Delete → settings reference + Keychain credential removed
```

## 7. 本地能力边界

### 7.1 音频采集

采集层使用 `AVAudioEngine` 或等价原生能力，同时提供 PCM frame、录音电平和临时 WAV。OpenDictation 现有权限、格式、音量计量和临时文件管理可以参考，但只在停止后返回整段 WAV 的实现不足以支持 VAD 分段。

录音达到 9 分 30 秒时给出不打断语音的视觉提示；达到 10 分钟时自动结束并进入尾段处理。自动结束等同于用户主动结束，不得丢弃已录内容。

### 7.2 SenseVoiceSmall

- 运行时：sherpa-onnx Swift/macOS；
- 模型：技术探针通过后冻结确切 int8 ONNX 版本、来源与校验和；
- 输入：16kHz 单声道语音段；
- 场景：普通话、粤语、中英混合随机出现；
- 输出：文本、可用的语言或事件标签、处理耗时。

`originalText` 是去除模型控制标签后的用户可读 ASR 文本。模型标签作为诊断元数据保存，不能混入复制内容。

0.1 只有一个 `audio segment → transcript` 边界，不实现 ASR Provider 配置中心。

### 7.3 保守清理

允许的操作：

- 规范首尾空白和明显重复空格；
- 合并连续重复标点；
- 删除位于段落边界或连续重复、且不承担肯定、犹豫或情绪含义的独立“嗯、啊、呃、额”等填充音。

禁止自动修改：

- 数字、日期、金额、专有名词和英文术语；
- 否定词和否定关系；
- 自我纠正前后的内容；
- “然后、但是、所以、就是”等可能承载逻辑的连接词；
- 有效表达态度、情绪或思考过程的语气词；
- 句序、论证结构和表达风格；
- 任何规则无法确定意图的内容。

清理器必须返回 `EditOperation`，使每次删除或规范化都可追溯。没有足够可靠的 ASR 置信信息时，不得以“高置信度”为名删除内容。

### 7.4 剪贴板

使用 `NSPasteboard` 写入本地清理文本，不模拟 `Command + V`，不需要辅助功能权限。写入成功后不恢复旧剪贴板；写入失败时保留上一份剪贴板和本地记录，并提供手动重试。

只有交付协调器能自动写剪贴板。录音、ASR、清理器和 UI 回调均不能直接写入。

## 8. UI 与交互设计

### 8.1 设计策略

TSB 不照搬 OpenDictation 的内容布局，也不在 0.1 从零建立完整视觉系统：

- 复用刘海定位、无焦点窗口、跨 Space/全屏、sleep/wake 恢复、波形和基础动画；
- 重新设计 TSB 的状态、文字预览、结果卡和设置页；
- 参考相似开源 Mac 产品的动效和信息密度，但不复制品牌资产，复用代码前先核对许可证；
- 优先使用 macOS 原生半透明材质、层级、阴影和动效，形成类似 Liquid Glass 的聚焦感；
- 先用 SwiftUI 低保真状态稿验证链路，不在 0.1 投入完整高保真设计系统。

### 8.2 单会话状态

```text
Idle
  → Recording
  → Processing
  → Result / Error / Cancelled
  → Idle
```

- `Idle`：刘海收起，只监听快捷键。
- `Recording`：主卡展开，展示波形、计时和稳定段落预览。
- `Processing`：展示尾段转录与本地整理状态。
- `Result`：展示实际复制文本、原文入口和“已复制”状态。
- `Error`：说明录音、转录、保存或复制中的具体失败，并给出适用恢复动作。
- `Cancelled`：短暂反馈后收起，不保存、不复制。

### 8.3 多会话焦点层级

用户在上一条仍处于 `Processing` 时按下新快捷键：

1. 新录音立即成为刘海主卡，不等待旧任务；
2. 上一条缩成刘海下方的紧凑次级卡，显示“处理中、已完成或失败”；
3. 次级卡不得抢焦点、改变主卡状态或阻止新录音；
4. 同时最多显示一个次级卡，更早结果进入最近记录；
5. 所有异步回调按 `sessionID` 回到各自卡片，不能串到当前会话。

0.1 的次级卡承载本地 ASR 尾段和保存状态。0.2 可沿用同一视觉规则承载最多约 3 秒的 LLM 任务，但 0.1 不实现 LLM 状态。

### 8.4 设置页

0.1 可操作项只有：

- 快捷键模式和组合；
- 原始转录保留时长；
- API Provider 预设、模型、HTTPS Base URL 和 API Key；
- `Save`：校验本地字段后保存，Key 写入 Keychain；
- `Cancel`：放弃当前未保存编辑；
- `Delete`：二次确认后删除配置引用和 Keychain 凭证。

API 区域固定展示“为 0.2 提前配置；0.1 不会连接服务商或发送文本”。不提供测试、启用 AI、优化、重试等按钮。

## 9. 幂等与并发规则

每次听写在开始时创建唯一 `sessionID`：

- 只有录音槽处于 `Idle` 时才创建新会话；后台仍有 `Processing` 会话不阻止新建。重复的 key-down 不得重复开始。
- 每个会话设置 `stopRequested` 闩锁；重复的快捷键、key-up 和停止回调只执行一次停止。
- 每个 VAD 段包含递增 `segmentSequence`；同一段最多追加一次，乱序结果按序组装。
- 清理和持久化对同一 `sessionID` 最多成功一次。
- 每个会话最多自动复制一次；手动复制可重复执行，但不能创建新记录。
- UI 延迟动画和异步回调必须携带 `sessionID`；旧回调不能关闭或改写新会话窗口。
- API 设置保存采用当前草稿版本号；旧的异步 Keychain 回调不能覆盖更新后的草稿。
- 删除 API 配置重复执行时仍得到“配置不存在”的安全终态，不产生孤立 Keychain 项。

多个会话完成顺序不一致时，较旧会话不得覆盖已经由较新会话交付的剪贴板。较旧结果仍保存并显示“需要手动复制”。


`FutureAIProfile` 只引用 Keychain 条目，不包含 API Key 明文，也不被 0.1 听写链路读取。

生命周期：

- 本地清理文本默认保留到用户删除；
- 原始转录默认 7 天，可配置 1 天、7 天、30 天或永久；
- 成功音频在文本原子写入后立即删除；
- 失败音频最多保留 24 小时，缓存硬上限 2GB，超限优先删除最旧文件；
- 删除听写记录时同时删除关联文本、修改记录和失败音频。

0.1 不上传音频或文本，不做遥测。日志不得记录完整音频、完整转录、剪贴板、API Key 或 Keychain 内容。

## 11. 错误处理与恢复

- 麦克风权限缺失：不进入录音，提供系统设置入口。
- 音频设备中断或切换：安全结束；有音频则建立恢复记录，否则取消。
- VAD 段识别失败：继续录音并保留音频，结束后允许整次重试。
- ASR 加载失败：保留音频 24 小时，提供重新加载入口。
- 清理失败：保存并复制原始转录，不阻塞交付。
- 本地写入失败：不删除音频，不显示“已保存”。
- 剪贴板失败：文本仍保留，手动重试不触发重新 ASR。
- 10 分钟自动结束：与主动结束走同一条尾段、保存和复制路径。
- 应用崩溃：下次启动清理无效临时文件，并恢复 24 小时窗口内的失败音频。
- 空录音：不创建成功记录，不覆盖剪贴板。
- API Save 失败：保留当前草稿并显示本地错误；不得留下配置引用与 Keychain 凭证不一致的半成功状态。

## 12. 性能与资源目标

以下目标在 M5 Pro、48GB 内存、模型已加载时测量：

- 快捷键到录音反馈：不超过 200ms；
- 完成语音段到稳定预览：P95 不超过 1.5s；
- 15 秒听写结束到复制：P95 不超过 3s；
- 3–5 分钟听写结束后只处理尾段，P95 不超过 4s；
- 10 分钟录音可以完成分段、保存和最终交付，无崩溃、无截断；
- 本地识别实时因子 RTF 不高于 0.5；
- 空闲时不占用麦克风；
- ASR 活跃期间新增峰值内存目标不超过 2GB；
- SenseVoice 模型和运行时新增磁盘目标不超过 500MB。

冷启动模型加载、功耗和温度必须记录，但不先假设通过值。若首段冷启动明显影响体验，优先采用启动后空闲预热或延迟卸载，不引入常驻麦克风。

## 13. 测试策略

### 13.1 SenseVoice 技术探针

正式改造客户端前，先在目标 Mac 冻结模型版本并验证：

- 普通话、粤语、中英混合均能识别；
- 3–5 分钟和 10 分钟音频不会崩溃或截断；
- 冷/热延迟、RTF、峰值内存和模型体积被真实记录；
- 取消、尾段和连续分段结果可以稳定回收。

探针不通过时停止客户端扩建，先解决或替换 ASR 基线。

### 13.2 用户 Golden Set

首轮至少 80 条真实或同风格口述：

- 25 条普通话或轻口音普通话；
- 20 条粤语；
- 20 条中英混合；
- 15 条自然随机切换或无法预先归类的口述。

另外保留 3 条 3–5 分钟样本和 1 条 10 分钟样本。语料覆盖停顿、重复语气词、自我纠正、思绪中断、数字、否定词、人名、产品名和技术术语。

记录 CER/WER、关键实体错误、RTF、冷/热延迟、峰值内存和“无需手改即可粘贴”的比例。总体准确率不得掩盖任一语言场景的明显退化。

### 13.3 稳定性与隐私

- 连续完成 100 次开始、结束和复制，无崩溃、卡死、重复复制或丢失文本；
- 覆盖 20 次取消、睡眠唤醒、屏幕变化和麦克风切换；
- 覆盖新录音与旧会话 `Processing` 重叠、乱序完成和迟到 UI 回调；
- 验证较旧会话不能覆盖较新会话已经交付的剪贴板；
- 验证录音成功、清理失败、磁盘失败、复制失败、空录音和 10 分钟自动结束；
- 验证 0.1 听写过程中无外部网络请求；
- 验证 API 配置 Save/Cancel/Delete、Keychain 半失败恢复和日志脱敏。

## 16. Multi-Agent 执行规则

本节只描述开发协作，TSB 产品运行时不包含多 Agent。

### 16.1 最小分工

| 角色 | 主要职责 |
|---|---|
| Sol | 规格、接口冻结、阶段门、任务分派、集成审查和最终验收 |
| Terra | Swift 主实现、OpenDictation 精简、音频/VAD、状态机、UI 和本地主链路 |
| GPT-5.5 | SenseVoice/sherpa-onnx 技术探针及明确的疑难构建问题 |
| Luna | Golden Set runner、回归测试、隐私检查和机械性验证 |

### 16.2 执行顺序

1. Sol 冻结当前规格和最小公共数据结构。
2. GPT-5.5 只做 SenseVoice 技术探针；Terra 同期只整理不涉及 ASR 的客户端壳。
3. 探针通过后，Terra 串行接通录音、VAD、ASR、清理、保存和复制。
4. 状态契约稳定后，Terra 实现 TSB 刘海 UI 和 API 预配置页。
5. Luna 在不修改共享业务实现的前提下运行回归、Golden Set 和隐私检查。
6. Sol 检查实际 diff、构建、测试和真机结果后决定阶段是否通过。

同一共享文件同一时间只有一个写入者。状态机、应用编排、公共数据结构、工程配置和依赖文件禁止多人并行修改。默认不为了“看起来并行”让多个代理重复阅读或实现同一路径。

### 16.3 Token 控制

- 20x Pro 周额度不是公开固定的 Token 数，不能承诺精确占比。
- 完整 0.1 粗估消耗约 80 万–250 万原始开发 Token；SenseVoice 构建或性能问题可能把上限推高到约 300 万。
- 每个代理只获得当前工作包所需文件与契约，禁止重复加载整仓上下文。
- 每个内部阶段只进行一次独立审查；机械测试优先交给 Luna。
- SenseVoice 探针未通过时立即停止 UI 和留存扩建，避免在错误 ASR 基线上消耗额度。
- 语音唤醒和生成式 LLM 后移预计避免至少 30% 的额外开发与验证范围。

## 17. 0.1 验收标准

0.1 只有同时满足以下条件才算完成：

1. 两种快捷键均可稳定开始、结束和取消录音。
2. 刘海能即时反馈录音，并按稳定段落展示准实时转录。
3. SenseVoiceSmall 在目标 Mac 本地处理随机出现的普通话、粤语和中英混合。
4. 典型 3–5 分钟与最长 10 分钟录音无截断、无丢失，结束后在目标时间内交付。
5. 每次成功听写保存独立的原始转录、本地清理文本和修改记录。
6. 清理器不改变数字、实体、否定关系、句序或原意。
7. 每个会话最多自动复制一次；乱序完成和迟到回调不能覆盖较新交付。
8. 新录音不等待旧会话处理，刘海主卡与次级卡状态互不串线。
9. API 配置可以安全 Save、Cancel 和 Delete，0.1 不读取该配置发起网络请求。
10. 文本和失败音频严格按本地策略处理，日志不泄露文本、音频或 Key。
11. Golden Set、性能目标、100 次稳定性循环和失败恢复检查通过。
12. 不存在 LLM 调用、语音唤醒、光标插入、Agent、知识库、TTS 或云端音频路径。

## 18. 后续阶段

### 0.2 文本分层与可选 LLM

- 使用用户自己的 API 配置，只发送本地清理文本，不发送音频；
- LLM 的唯一首版职责是把用户想法分层，不做自由润色或事实补写；
- 原文、本地清理文本和 LLM 分层结果分别保存；
- 根据 0.1 的真实文本长度决定输入、输出、费用、分段和超时上限；
- 一次会话最多一个有效 LLM 任务，默认约 3 秒后允许用户继续使用本地结果；
- 用户开始新录音时，新录音占据刘海主卡，旧 LLM 任务缩入下方次级卡，迟到结果不得覆盖较新的剪贴板；
- 完成 API 连接测试、Provider 合同、明确的文本出站授权和隐私说明；
- 增加签名、模型下载和小范围测试分发。

LLM 允许改变文字的范围，需要通过 0.1 真实样本另行设计和确认；在规则冻结前，不把“保真优化”当作已解决问题。

### 0.3 无感唤醒与直接插入

- 独立的本地低功耗唤醒层和硬关闭开关；
- 支持固定词、特定语气或个人习惯信号的可验证激活条件；
- 激活后进入正常录音，持续无声约 10 秒自动熄火；
- 评估超过 2–3 秒停顿、长音、误触发、漏触发、功耗和隐私反馈；
- 增加可选的当前光标直接插入。

语音唤醒必须先定义可观测的触发条件和误触发上限，不能仅凭“听起来无感”直接实现。

### 0.4 第二大脑

- 把用户确认保留的文本转为想法、项目记录和待办候选；
- 建立个人知识库、长期记忆和可恢复的项目上下文。

后续能力必须消费 0.1 保存的原文、清理文本和段落顺序，不允许覆盖或破坏来源链路。
