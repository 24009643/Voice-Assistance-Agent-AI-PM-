# TSB 0.1 Alpha 2 Master Plan

> **For agentic workers:** execute task-by-task with `superpowers:subagent-driven-development`; one implementation writer at a time, task review after every task, whole-branch review before merge.

**Goal:** Add a real-time local draft, retain aligned private audio/text sessions, visibly confirm clipboard delivery, improve terminology handling, support controlled corpus export, and add an optional text-only LLM review without implementing training.

**Spec:** `docs/specs/tsb-v0.1-alpha2-design.md`

**Decision:** `docs/decisions/ADR-0004-alpha2-adaptive-dictation.md`

**Baseline:** `main` at `584a7b1`; Alpha app tests 48/48 and SenseVoice probe 7/7 passed in the isolated `codex/wp-04-alpha2` worktree before this plan was written.

## Global constraints

- Canonical repo: `/Users/zhuohengchi/Desktop/The Second Brain`.
- Product: native Swift 6 macOS 14+ app; target validation device M5 Pro/48 GB.
- Reuse sherpa-onnx 1.13.6. Do not add another speech dependency unless a failing gate proves it necessary and ADR-0004 is revised.
- One session owns one bundle and one automatic clipboard delivery.
- Audio, transcripts, credentials, model weights and private/export artifacts stay outside Git by default.
- Audio has no network path. Optional LLM review receives explicit text only and never blocks local delivery.
- Do not add post-training, fine-tuning, pseudo-labeling, LLM training-data generation, background dataset upload, voice wake, simulated paste or speculative scaffolding for them.
- Every implementation task starts with a failing focused test or probe, then the smallest production change, then focused/full verification and one reversible commit.
- Weekly allowance is read from the Codex UI; stop new work at 55% remaining. This environment cannot programmatically read the account percentage, so the execution record must mark the manual guard state before each WP.

### G-A2-ASR

- Model directory validates encoder, decoder, tokens, license and SHA-256 manifest.
- The 1.13.6 Swift online API builds without another dependency.
- Mandarin, Cantonese and Chinese-English samples produce changing online output and a non-lost final tail.
- Target evidence records cold/warm load, first update, RTF, peak memory, finish and cancel.
- Dynamic Paraformer hotword support is reported unsupported rather than advertised.

### G-A2-DATA

- New captures use `Sessions/<UUID>/audio.wav` and `record.json`.
- Success, ASR failure and no-speech retain aligned bundle data; cancellation removes only its own bundle.
- Legacy flat JSON remains readable and untouched.
- Clipboard truth and UI truth match, including the “copied but status write failed” case.

### G-A2-LIVE

- One PCM stream writes the final WAV and feeds Paraformer; there is no full PCM memory duplicate.
- Preview is never copied or persisted as authoritative final text.
- SenseVoice final is copied once; non-empty streaming fallback is used only if SenseVoice fails.
- First preview P95 <=800 ms, stop-to-final P95 <=1.5 s, stop-to-copy P95 <=2 s and hard maximum <=3 s on the target data set.
- Rapid start/stop/cancel and the 10-minute limit release tap, engine, file and recognizers exactly once.

### G-A2-TRUST

- Exact alias correction leaves unmatched similar words unchanged and persists edit provenance.
- Session bundles stay the only private corpus; no duplicate store or implicit acceptance inference.
- Export is local, selected and previewed; public audio needs a separate confirmation and publication is never automatic.
- API profile Save/Cancel/Delete is real, keys stay in Keychain, and text review DTOs cannot carry audio or paths.
- Reviewer timeout/error/invalid JSON does not change local result or clipboard.
- Repository search and network tests prove training, audio upload, wake word and automatic paste paths are absent.

## Execution order and ownership

Sol owns ADR/spec/plan/AC decisions, integration gates, final review, merge and publication. Each task receives one fresh implementation agent and one fresh reviewer through the SDD ledger. Shared files (`project.yml`, `SessionCoordinator`, domain models, app entry and the acceptance matrix) never have multiple implementation writers.

Read-only discovery may run in parallel. Product implementation is sequential in this order:

1. WP-A2-00 documentation freeze.
2. WP-A2-01 streaming gate.
3. WP-A2-02 session bundle/copy truth.
4. WP-A2-03 product integration.
5. WP-A2-04 trust features.
6. WP-A2-05 whole-branch evidence and adversarial review.

## Verification and publication

Every code WP runs focused tests, the complete macOS test suite, the SenseVoice probe, `git diff --check`, secret/binary checks and a clean build. Real microphone and target-Mac latency evidence are mandatory before an acceptance item becomes `passed`.

Merge and push are side effects outside the feature worktree. They happen only after the Alpha 2 RC review and the previously granted publication authorization still applies. Use merge commits or fast-forward as appropriate; never force-push.
