# TSB 0.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to execute this plan task-by-task. Use `superpowers:test-driven-development` for each production change and `superpowers:verification-before-completion` before claiming a gate passed.

**Goal:** Add a horizontal Dynamic Island capture/result UI and an optional asynchronous organizer that preserves the 0.1 local-save-and-copy contract, returns numbered points, links only real internal TSB records, and keeps speculative connections visibly separate.

**Architecture:** Keep `SessionCoordinator` as the single runtime owner. The existing capture axis remains unchanged through local save and one clipboard delivery. A second per-session organization axis begins only after copied delivery status has been persisted, owns no audio or clipboard dependency, persists its pending/success/failure state in the existing `record.json`, validates strict JSON, and publishes display-only state through `AppSnapshot`. Only one model request runs at a time. The UI renders snapshots and sends intents; Settings owns one OpenAI-compatible endpoint and versioned consent.

**Tech Stack:** Swift 6, SwiftUI, AppKit, Foundation `URLSession`, Security.framework Keychain, `UserDefaults`, NaturalLanguage, CryptoKit, XCTest, existing sherpa-onnx 1.13.6. No new package dependency.

**Spec:** `docs/superpowers/specs/2026-08-20-tsb-v0.2-first-principles-design.md`
