# TSB 0.2 Recording Runtime Completion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make one resident TSB process reliably discover the validated local Paraformer bundle, show live text or an explicit fallback, and expose unambiguous recording Stop/Cancel controls before closing the remaining v0.2 acceptance gates.

**Architecture:** Keep `SessionCoordinator` as the single recording-state owner and `AudioRecordingService` as the single PCM/WAV source. Resolve Paraformer from an explicit development override or the canonical Application Support directory, carry availability through `AppSnapshot`, and render it through the existing island plus a native SwiftUI menu-bar surface. SenseVoice remains the authoritative final transcriber and no new dependency or silence detector is added.

**Tech Stack:** Swift 6, SwiftUI, AppKit, AVFoundation, Carbon, sherpa-onnx 1.13.6, XCTest, XcodeGen, macOS 14+

**Spec:** `docs/superpowers/specs/2026-08-25-tsb-v0.2-recording-runtime-design.md`

## Global Constraints

- Use the existing linked worktree and branch `codex/wp-04-alpha2`; do not create another worktree.
- One shared-code implementer owns all production/test edits. Review and acceptance agents are read-only.
- Do not add dependencies, auto-download models, add cloud ASR, or send audio/text/network requests during automated work.
- Idle TSB may remain resident; idle TSB must not open or monitor the microphone.
- Preserve exact Stop, Cancel, durable-save, one-copy, privacy, Keychain, and organization semantics.
- Keep the 10-minute hard limit; do not add silence-based stopping or launch-at-login in v0.2.
- Never log model paths, transcript bodies, audio, API keys, Authorization headers, or private session contents.
- Real microphone, Provider, record creation, process termination, M09 annotation, M10 execution, merge, push, and release remain explicit authorization gates.
- Every code task follows RED -> minimal GREEN -> focused verification -> self-review commit -> independent review.

Add to `ParaformerModelLocation` and retain the existing manifest validation in `init(directory:)`:

```swift
static let modelName = "sherpa-onnx-streaming-paraformer-trilingual-zh-cantonese-en"

static func resolvedLocation(
    environment: [String: String] = ProcessInfo.processInfo.environment,
    applicationSupportDirectory: URL? = FileManager.default.urls(
        for: .applicationSupportDirectory,
        in: .userDomainMask
    ).first
) throws -> ParaformerModelLocation {
    if let override = environment["TSB_PARAFORMER_MODEL_DIR"], !override.isEmpty {
        return try ParaformerModelLocation(directory: URL(fileURLWithPath: override, isDirectory: true))
    }
    guard let applicationSupportDirectory else {
        throw ParaformerPreviewError.missingDevelopmentModelDirectory
    }
    let directory = applicationSupportDirectory
        .appendingPathComponent("TSB/Models", isDirectory: true)
        .appendingPathComponent(modelName, isDirectory: true)
    return try ParaformerModelLocation(directory: directory)
}
```

Keep `developmentLocation(environment:)` as a compatibility wrapper that calls `resolvedLocation(environment:applicationSupportDirectory: nil)`. The product AppController uses `resolvedLocation()`; environment-only tests and development callers keep their existing strict behavior.
