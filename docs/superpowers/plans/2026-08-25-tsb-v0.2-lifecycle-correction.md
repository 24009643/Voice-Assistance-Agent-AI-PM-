# TSB 0.2 Lifecycle Correction Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Correct shutdown, serialized-intent ownership, and privacy-receipt rendering without regressing the recording runtime work already present on `codex/wp-04-alpha2`.

**Architecture:** Keep `SessionCoordinator` as the session-state owner, but separate three meanings that the rejected fix conflated: destructive cancellation of incomplete capture, cancellation of background tasks, and in-memory UI teardown. Keep independent recording/organization lanes while registering every running or queued controller task. Keep organization receipt metadata content-free and render it through the actual failed/cancelled view and reopen path.

**Tech Stack:** Swift 6, SwiftUI, AppKit, AVFoundation, XCTest, XcodeGen, macOS 14+

**Spec:** `docs/superpowers/specs/2026-08-25-tsb-v0.2-recording-runtime-design.md` plus `docs/superpowers/specs/2026-08-20-tsb-v0.2-first-principles-design.md`

## Global Constraints

- Work only in the existing linked worktree and branch `codex/wp-04-alpha2`.
- One production/test writer at a time; every task receives an independent read-only review.
- Preserve Stop as durable-save/final/copy-once and Cancel as deletion of incomplete capture.
- A delivered session and its `record.json` must survive application shutdown regardless of background history work.
- Recording controls and organization controls are independently serialized; shutdown cancels every running and queued controller task.
- Every `await historySuggestions` continuation fails closed on task cancellation, shutdown, session identity, transcript identity, and request identity before any state write.
- Receipt metadata contains dispatch state and counts only; never transcript text, summaries, record IDs, paths, keys, headers, or Provider payloads.
- No new dependency, cloud ASR, silence stop, login item, background microphone, or automated real mic/Provider/user-Keychain/System-Settings/record/network/process side effect.
- Every production change follows RED -> minimal GREEN -> focused verification -> self-review commit -> independent review.

- [ ] **Step 1: Add a real durable-directory RED test**

Create a temporary Sessions root shared by a real `TranscriptStore` and the production recorder cancellation implementation. Drive a session through Stop, durable save, and delivery; block its post-copy history load; call `shutdown()`; then assert the exact saved `record.json` remains readable.

```swift
func testShutdownDuringDeliveredHistoryLoadPreservesDurableRecordAndStartsNoOrganization() async throws {
    try await withTemporarySessionsRoot { root in
        let harness = try DurableShutdownHarness(root: root, blockHistory: true)
        let sessionID = try await harness.deliverOneSession()
        await harness.waitUntilHistoryStarts()

        harness.coordinator.shutdown()
        await harness.releaseHistory()

        XCTAssertEqual(try harness.store.load(id: sessionID)?.id, sessionID)
        XCTAssertEqual(harness.organizationInputs.count, 0)
        XCTAssertEqual(harness.providerStarts, 0)
        XCTAssertEqual(harness.coordinator.snapshot.status, .idle)
    }
}
```

The test must use the real destructive session-directory behavior, not a counter-only `cancelRecording` fake.
