# TSB 0.2 Recording Runtime Completion Design

- Status: approved in chat; pending written-spec review
- Date: 2026-08-25
- Branch: `codex/wp-04-alpha2`
- Source baseline: `ad5b9ad`
- Parent design: `docs/superpowers/specs/2026-08-20-tsb-v0.2-first-principles-design.md`

## 1. Outcome

Complete the daily capture loop so one resident TSB process is visibly ready, microphone access is requested once and used only during recording, live Paraformer text appears while speaking, and every recording exposes unambiguous Stop and Cancel actions.

The product flow remains:

```text
TSB launched and Ready
  -> Option-Space or menu Start
  -> microphone opens for this recording only
  -> PCM drives WAV + level + Paraformer live draft
  -> Option-Space / visible Stop / 10-minute limit
  -> SenseVoice final -> durable record -> one clipboard copy

Escape
  -> cancel this recording -> remove incomplete bundle -> Ready
```

The application may remain resident; the microphone may not. There is no idle audio capture, wake word, background listening, or cloud ASR.

## 2. Confirmed current gaps

1. The validated Paraformer bundle exists on the target Mac, but current TSB processes do not receive `TSB_PARAFORMER_MODEL_DIR`.
2. `AppController` uses `try?` for Paraformer resolution. Any missing path, file, manifest, or checksum becomes `nil` without an observable product reason.
3. `LivePreviewPipeline` intentionally becomes a no-op when its model location is `nil`, so recording and final SenseVoice can work while live text remains empty.
4. Recording UI has a Stop control in source, but lacks visible Option-Space/Escape guidance and a running duration. The target user did not see a usable Stop affordance.
5. Option-Space already toggles start/stop; Escape cancels and removes the incomplete session. Only the latter behavior is currently obvious to the user.
6. The only automatic stop is the existing 10-minute hard limit. There is no silence-based stop.
7. The app has no menu-bar Ready/Recording surface or launch-at-login preference. Multiple Debug processes were observed during diagnosis, so manual evidence must be collected from one exact process.

## 3. Product decisions

### 3.1 Resident means app-ready, not microphone-open

- While TSB is launched, one menu-bar item shows `Ready`, `Recording`, or `Processing`.
- The menu provides Start/Stop, Cancel when applicable, Settings, and Quit.
- Option-Space remains the global start/stop shortcut; Escape remains cancel while recording.
- The microphone opens only after an explicit Start and closes exactly once on Stop, Cancel, device failure, app termination, or the 10-minute limit.
- Launch at login is deferred. If added later, it must be an explicit user-controlled preference.

### 3.2 Microphone permission

- macOS microphone permission is requested only when authorization is `.notDetermined` and the user starts the first recording.
- An authorized app starts the same recording without a second click.
- Denied or restricted access does not enter recording. The island and menu show a clear explanation and an Open System Settings action.
- A stable installed app identity is the release target. Repeated prompts caused by changing Debug identities or multiple processes are not accepted as product behavior.

### 3.3 Paraformer resolution

Resolution order is fixed:

1. `TSB_PARAFORMER_MODEL_DIR`, when explicitly set for development or acceptance.
2. The bootstrap script's canonical Application Support model directory for `sherpa-onnx-streaming-paraformer-trilingual-zh-cantonese-en`.
3. Unavailable with a typed, non-sensitive reason.

Every candidate must pass the existing file, license, manifest-size, manifest-format, and checksum validation before a recognizer is created. The model is never downloaded automatically by the app.

The environment override remains useful for isolated tests; it is no longer the only product lookup path.

### 3.4 Observable preview degradation

Paraformer failure must not block recording or final SenseVoice. It must also not be silent.

During recording without live preview, the island and menu show:

> 实时草稿不可用，停止后仍会生成全文

The reason category may be logged as non-sensitive metadata, but model paths, audio, transcript text, and manifest contents are not logged.

### 3.5 Recording controls and timing

The recording island always shows:

```text
录音中 00:12 · ⌥Space 停止 · Esc 取消
```

It retains visible `停止` and per-session `仅本地` controls. Stop and the second Option-Space preserve the recording and continue to final transcription. Escape cancels and deletes only the incomplete session.

The elapsed value is derived from the active session start time and advances while recording. The island also makes the 10-minute maximum discoverable before the limit is reached.

### 3.6 Automatic stopping

TSB 0.2 keeps the existing 10-minute hard stop and does not add silence-based automatic stopping. A short silence threshold can truncate thought pauses and requires a separate calibration set, countdown behavior, and acceptance gate. That work is deferred until the live preview and explicit Stop flow pass M10.

## 4. Runtime boundaries

- `AppController` owns model resolution, permission state, hotkeys, and menu commands.
- `SessionCoordinator` remains the single owner of recording session state and Stop/Cancel semantics.
- `AudioRecordingService` remains the single PCM/WAV source and retains the 10-minute terminal limit.
- `LivePreviewPipeline` and a per-session `ParaformerPreviewTranscriber` own preview-only ASR.
- `SenseVoiceTranscriber` remains authoritative for the post-Stop final candidate.
- `IslandPresentation` and the menu render state and emit intents; they do not access audio, ASR, storage, Keychain, clipboard, or network clients.

No new dependency, model SDK, recorder, provider SDK, or background agent is introduced.

## 5. State and failure behavior

| Condition | Recording | Live draft | Final transcript | User-visible behavior |
|---|---|---|---|---|
| Both models valid | continues | Paraformer | SenseVoice preferred | normal recording UI |
| Paraformer missing/invalid | continues | unavailable | SenseVoice | explicit preview-unavailable message |
| SenseVoice missing at launch | blocked | not started | unavailable | existing model error, no microphone side effect |
| Microphone denied | blocked | not started | unavailable | explanation + Open System Settings |
| Audio device failure | ends once | cancelled | failure record when applicable | recording-failed state |
| Stop / second Option-Space | ends once | finalized | SenseVoice or streaming fallback | local review then durable copy |
| Escape | cancelled once | cancelled | not run | incomplete bundle removed, return Ready |
| 10-minute limit | ends once | finalized | normal final path | maximum-duration explanation |

## 6. Acceptance gates

### 6.1 Automated

- Resolver tests cover environment override, canonical default, precedence, missing files, malformed/oversized manifest, and checksum mismatch.
- App startup tests prove valid default Paraformer enables a real preview factory without an environment variable.
- Degradation tests prove missing/invalid Paraformer leaves recording and SenseVoice available and produces an observable preview-unavailable state.
- Recording presentation tests require duration, `⌥Space 停止`, `Esc 取消`, visible Stop, and the 10-minute limit explanation.
- Menu actions map to the same coordinator intents as hotkey and island controls.
- Existing cancellation, stale-callback, exact-once recording termination, persistence, clipboard, privacy, and organization tests remain green.
- Focused suites pass before one full macOS suite, both ASR probes, a fresh unsigned Debug build, diff checks, and current/additions sensitive scans.

### 6.2 Target Mac

Use one exact TSB process and record its build/commit identity.

1. First Start requests microphone permission once; granting it starts that same recording.
2. Later Starts from another foreground app do not request permission again.
3. Menu shows Ready while idle and the system shows no microphone use.
4. A 3-second Mandarin phrase produces a non-empty live draft; repeat for Cantonese and Chinese-English mix.
5. First live draft P95 is at most 800 ms.
6. Recording UI exposes elapsed time, visible Stop, Option-Space Stop, and Escape Cancel.
7. Stop preserves the session and reaches final local delivery; Escape removes the incomplete session and does not copy or dispatch.
8. App Quit unregisters hotkeys and leaves no active recorder, preview actor, incomplete audio, or background Provider request.

### 6.3 Remaining v0.2 release gates

- M09: at least 30 qualified real mixed-language records, including the current 22 only after manual qualification; complete coverage, meaning, invention, negation, link relevance, and speculative-isolation judgments.
- M10: after preview passes a short rehearsal, obtain fresh explicit authorization and run one new exclusive 100-cycle artifact set. It must meet every existing latency, record, copy, clipboard, and unique-session boundary.
- Independently review the implementation `BASE..HEAD`; Critical and Important findings block continuation.
- Owner decides reachable-history and historical-extra-record disposition. No history rewrite, deletion, rotation, merge, push, or release is implicit.

## 7. Multi-agent execution

Use one shared-code implementer. `AppController`, `SessionCoordinator`, audio, Paraformer, island/menu, settings/permission, clipboard, and acceptance-runner code are single-writer.

Two agents may work in parallel only as read-only roles:

1. Specification/security/concurrency reviewer over the exact `BASE..HEAD` diff.
2. Acceptance/evidence verifier for focused tests, target-Mac checklist, M09/M10 boundaries, and ledger consistency.

Each code task closes as:

```text
failing test -> minimal implementation -> focused test -> self-review commit
-> independent review -> same implementer fixes -> focused rereview -> ledger sync
```

Only one gate-level full suite is run after shared interfaces converge.

## 8. Out of scope

- Always-on microphone, voice wake, cloud ASR, continuous background listening.
- Automatic model download or training.
- Silence-based stopping in 0.2.
- Default launch at login.
- New transcript/history window, knowledge graph, Agent framework, or Obsidian integration.
- Reopening already-passed Provider and organization gates unless the new diff touches them or evidence conflicts.

## 9. Rollback

The implementation will be split into reviewable commits for model resolution/degradation, recording/menu UX, and evidence synchronization. Reverting those commits restores the current behavior without migrating or deleting user sessions.
