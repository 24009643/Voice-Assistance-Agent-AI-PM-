# TSB 0.2 第一性原理设计

- 状态：已形成实施建议，待进入代码迭代
- 日期：2026-08-20
- 基线：`codex/wp-04-alpha2` @ `64b808f`
- 视觉方向：三舱结果岛 + Alcove 式流体状态形变
- 产品边界：0.2 仅关联 TSB 内已有录音与整理记录

## 1. 结论

TSB 0.2 不是“第二大脑完整版”，而是给 0.1 增加一个**不干扰本地听写的异步结构化与受控回忆层**。

核心链路只有一条：

```text
说话
  -> 本地录音与实时转写
  -> 本地最终稿原子保存
  -> 本地稿自动复制一次
  -> 独立异步整理
  -> 编号要点 + 已知 TSB 记录关联 + 明确标记的推测连接
  -> 横向灵动岛展示
```

云端慢、失败、未授权或被切换为“仅本地”，都不能改变前四步，也不能阻止下一次录音。

## 2. 第一性原理：用户真正购买的是什么

用户不是在购买一个更大的窗口，也不是在购买“模型调用次数”。用户真正需要的是：

> 在想法消失前，以最低摩擦保存原意；随后用最少注意力把它变成可扫描、可追溯、可继续思考的结构。

因此 0.2 的优先级由六类损失决定：

| 优先级 | 必须最小化的损失 | 产品约束 |
|---|---|---|
| P0 | 灵感没有被捕获 | 整理永不阻塞录音和本地保存 |
| P0 | 原意被修改 | 原始转录、本地清理、整理输出分层保存 |
| P0 | 隐私越界 | 出站白名单；音频、路径、全量历史永不出站 |
| P0 | 剪贴板被迟到结果覆盖 | 仅本地稿自动复制，整理结果只能手动复制 |
| P1 | 用户注意力被 UI 打断 | 主流程只在顶部横向灵动岛中完成 |
| P1 | 关联或新想法被伪装成事实 | 已知关联与推测连接分区、分色、分数据类型 |

## 3. 十条不可破坏的产品守则

1. 捕获优先于整理。
2. 本地结果先保存、后复制，且自动复制最多一次。
3. `originalText` 与 `localCleanedText` 永不被整理任务改写。
4. 整理是可失败、可取消、可重试的派生结果。
5. 云端在完成一次明确授权后才可默认自动整理。
6. 每次录音都能在发送前切换为“仅本地”。
7. 云端自动整理只接收当前本地文本；历史摘要只能来自用户在本地建议中明确选中的记录。
8. “已有记录关联”只能落到真实存在的内部记录。
9. 新连接必须标记为“推测”，不得混入用户原意。
10. 旧任务的迟到回调不得抢占新录音、改写新会话或触碰剪贴板。

## 4. 0.2 产品形态

### 4.1 主交互：横向灵动岛

日常捕获、整理状态和整理结果都在屏幕顶部完成。完整应用窗口只承载设置、API、模型和隐私授权。

| 状态 | 建议尺寸 | 主要内容 | 可操作项 |
|---|---:|---|---|
| 静默 | 候选 `120 x 30` | 与硬件刘海融合 | 点击/下滑打开最近结果 |
| 录音 | 候选 `520 x 82` | 音量条、实时草稿、时长 | 停止、单次“仅本地” |
| 本地交付 | 候选 `520 x 82` | “本地稿已复制”、整理进度 | 收起、停止等待结果 |
| 整理结果 | 上限候选 `890 x 154` | 原文、编号要点、关联三舱 | 分舱切换、手动复制、收起 |
| 失败 | 候选 `520 x 82` | 保留本地稿与失败原因 | 重试、打开设置 |

宽度必须按当前屏幕可见区域收敛，不能越过安全边距。空间不足时用“原文 / 要点 / 关联”三个可点击分段页代替三舱并排；手势只能是快捷方式，每个操作都必须有可见按钮，录音/取消继续保留 Option-Space 与 Escape。

### 4.2 状态形变

视觉语言固定为 **NotchNook 式低矮模块组织 + 半透明玻璃 + Alcove 式流体状态反馈**，但只使用公开、稳定的 macOS 能力：

- SwiftUI/AppKit 原生动画；
- 录音时低成本音量条，不追求高成本真实波形；
- 录音开始立即成为主岛；
- 旧整理任务降为次级状态，不抢占主岛；
- 支持“减少动态效果”；
- 不依赖私有 API，不复制第三方隐私声明。

### 4.3 设置窗口

设置窗口只包含：

- 云端授权状态：未授权时关闭，授权后默认自动整理；
- 云端授权与数据范围说明；
- Provider、Base URL、Model、API Key；
- 一个 OpenAI-compatible 端点；可填写 HTTPS 云端或本机回环地址；
- 是否允许用户在单次确认后发送所选 TSB 历史摘要；
- 当前出站范围预览；
- 撤销云端授权和删除密钥。

API Key 只进入 Keychain；非敏感选项进入 `UserDefaults`。远程端点必须是 HTTPS，本机回环地址可使用 HTTP。撤销授权即关闭自动云端整理；“仅本地”保留为每次录音的单次选择，不再增加一个容易混淆的全局模式。

## 5. 两个正交状态轴

不要把录音、网络和 UI 合成一个巨型枚举。0.2 保留现有捕获轴，并增加独立整理轴：

```text
捕获轴：
Idle -> Recording -> Transcribing -> Saving -> LocalReady
                    \-> Cancelled / LocalFailed

整理轴：
NotRequested / LocalOnly / AuthorizationRequired
             -> Queued -> Organizing -> Organized
                                    \-> Failed / TimedOut / Cancelled
```

`LocalReady` 是唯一分叉点：先确认本地记录与剪贴板结果，再异步创建整理任务。整理任务不计入现有“最多三个转录任务”的容量，也不阻止新录音。

## 6. 最小数据模型

0.2 只在现有 `TranscriptRecord` 上增加一个可选的最新整理记录，不创建知识图谱、向量库或第二套记录系统。

```swift
struct OrganizationRecord: Equatable, Codable, Sendable {
    let requestID: UUID
    let inputTextSHA256: String
    let state: OrganizationPersistenceState // pending | succeeded | failed
    let provider: String
    let model: String
    let providerKind: ProviderKind
    let selectedRecordIDs: [SessionID] // 只保存在本地
    let output: OrganizationOutput?
    let errorCode: String?
    let updatedAt: Date
}
```

本地先把当前文本切成稳定的 `c1...cn` 片段。每个编号要点引用当前片段 ID；每个已知关联保留真实内部 `SessionID`；每个推测连接引用支持它的当前片段和历史候选 ID，并带固定的 `speculative` 类型。模型不生成 Swift 字符偏移，避免 UTF-8、UTF-16 与 `Character` 边界不一致。

任务入队前先把最小 `pending` 状态原子写回 `record.json`；成功或失败再覆盖该派生字段。第一版不保留多次运行历史，重试覆盖旧的派生结果，不触碰原始层。应用重启后把残留 `pending` 标成 `failed(interrupted)`，由用户决定是否重试，避免静默重复发送。

## 7. 整理合同

### 7.1 输入

整理输入只取 `localCleanedText`。不得直接把 `TranscriptRecord`、音频 URL 或完整会话对象传给网络层。

远程请求允许的字段：

```json
{
  "schema_version": "tsb.organization.request.v1",
  "request_id": "ephemeral-uuid",
  "current_segments": [
    {"segment_id": "c1", "text": "localCleanedText 的一部分"}
  ],
  "history_summaries": [
    {
      "candidate_id": "h1",
      "summary": "bounded summary"
    }
  ]
}
```

除了必要的协议版本和临时 ID，载荷只有当前文本片段和用户本次明确选择的历史摘要。默认自动整理的 `history_summaries` 为空。`candidate_id` 是单次请求内的临时编号。真实内部 UUID 不发送给模型；响应返回 `h1` 后由本地映射回真实记录。

明确禁止：音频、PCM、WAV、文件路径、API Key、剪贴板、完整历史、完整旧转录、日志和外部应用上下文。

### 7.2 输出

```json
{
  "schema_version": "tsb.organization.output.v1",
  "request_id": "same-uuid",
  "source_text_hash": "sha256",
  "no_result_reason": null,
  "numbered_points": [
    {
      "number": 1,
      "text": "不改变原意的要点",
      "source_segment_ids": ["c1"]
    }
  ],
  "known_record_links": [
    {
      "candidate_id": "h1",
      "reason": "与已有记录的关系",
      "source_segment_ids": ["c1"]
    }
  ],
  "speculative_connections": [
    {
      "statement": "可能的新连接",
      "why_speculative": "尚未被已有记录直接证实",
      "source_segment_ids": ["c1"],
      "candidate_ids": ["h1"]
    }
  ]
}
```

本地校验以下条件，任一失败则不展示为成功结果：

- JSON 与 schema 合法；
- `request_id` 和文本哈希匹配；
- 编号连续且要点只引用本次当前文本片段；
- 已知关联只引用本次候选编号；
- 推测连接没有混入已知关联；
- 空数组只能与 `insufficient_content` 或 `no_reliable_structure` 原因一起出现。

## 8. 历史选择：有限回忆，不做 RAG 平台

0.2 只扫描 TSB 自己的 `Sessions` 目录：

1. 排除当前记录、失败记录和没有可用文本的记录；
2. 本地选择器只产生“建议关联”，不会直接进入网络请求；
3. 优先使用旧记录已经保存的编号要点作为摘要；没有整理结果时不发送完整旧转录；
4. 使用系统 `NaturalLanguage` 分词；必须先通过正向文本相关性门槛，时间只用于同分排序；
5. 只选择超过阈值的最多 5 条；
6. 单条摘要最多 600 字，总计最多 3,000 字；
7. 无可靠候选时发送空数组。

默认自动整理只处理当前文本。连接舱先在本地展示建议记录；用户勾选并点击“生成关联”后，系统冻结本次候选 allowlist，仅发送这些记录的有界摘要。总授权允许发送“用户所选摘要”，但不能替代每次具体选择。

这个方案的上限是中小规模个人记录；当本地扫描被真实数据证明变慢或相关率不够时，再评估嵌入索引。0.2 不预建向量数据库。

## 9. Provider 策略

0.2 只实现一个 OpenAI-compatible 调用合同，不建设 Provider 市场：HTTPS 地址可用于 BYOK 云模型；本机回环地址可连接用户自行配置的本地模型。这样同时保留云端与本地选择，但没有两套 SDK、两套响应协议或 Provider 注册系统。

单次选择“仅本地”时：若当前配置是回环端点，则在本机整理；若当前配置是云端，则只运行确定性的基础分点，已知关联和推测连接保持为空。它不会回退到云端，也不会后台无限重试。

使用系统 `URLSession`、`Security`、`UserDefaults` 和 `NaturalLanguage`，不新增第三方依赖。

## 10. 并发、取消与失败

- 同一时间最多一个模型整理请求；后续记录以持久化 `pending` 状态顺序等待，但不占用录音/ASR 容量。
- 远程超时：20 秒后取消并忽略迟到响应；本地回环端点超时：60 秒。
- 开始新录音：新录音成为主岛，旧整理可以在后台继续。
- 录音期间可切换“仅本地”；Stop 时冻结该会话策略。请求发出后开关替换为“文本已发送”和“停止等待结果”，取消只能停止等待，不能撤回已披露的数据。
- 未授权：不发请求，显示授权入口。
- 鉴权、断网、无效 JSON：保留本地稿，提供一次明确重试按钮。
- 重试：只重跑整理，不重新录音、不重新复制。
- 任何整理代码都不持有 `ClipboardService` 或音频 URL。

隐私日志只记录 request ID、provider 类型、耗时、字符数、哈希、被选中的本地记录 ID 和错误码，不记录文本、Prompt、响应、密钥或路径。

## 11. 迭代顺序

### 0.2-A：岛形态迁移与零回归

- 把现有录音、复核、复制状态迁入横向灵动岛；
- 实现紧凑窗口尺寸、点击区域、停止按钮、单次“仅本地”；
- 把完整窗口改为设置窗口；
- 暂不连模型。

通过条件：0.1 真机录音、保存、复制和并发能力全部不回退。

### 0.2-B：整理数据合同与本地假实现

- 增加独立整理轴、严格数据模型、稳定片段 ID、哈希和 schema 校验；
- 用确定性本地整理器把句段编号，关联与推测保持为空；
- 完成三舱结果岛及手动复制。

通过条件：新录音可在旧整理期间立即开始；整理永不调用剪贴板。

### 0.2-C：云端授权与真实整理

- Keychain、一次授权、OpenAI-compatible HTTPS；
- 出站白名单、超时、取消、无效输出处理；
- 接通当前文本的编号整理。

通过条件：未授权和“仅本地”产生零远程请求；云端故障不影响本地链路。

### 0.2-D：内部关联与推测连接

- 增加内部记录扫描和有限候选选择；
- 在连接舱展示本地建议，只有用户明确选择并点击“生成关联”后才发送有界摘要；
- 本地验证已知链接，推测连接独立展示；
- 验证同一个 OpenAI-compatible 合同可使用本机回环端点。

通过条件：所有已知链接 100% 能解析到现存 TSB 记录；推测内容 100% 位于独立区域。

### 0.2-E：真机与内容质量发布门

- 完整自动测试、真实麦克风、断网、超时、并发和隐私审计；
- 使用用户真实中英粤混合 Golden Set 检查意义保持；
- 完成视觉、VoiceOver、现有快捷键和减少动态效果验收。

## 12. 验收门

### 本地链路

- 复用 0.1 的明确门槛：首个实时草稿 P95 不高于 800 ms，停止到本地最终稿 P95 不高于 1.5 s，停止到复制 P95 不高于 2 s且硬上限 3 s。
- 100 次完整循环：零丢记录、零重复自动复制、零整理结果覆盖剪贴板。
- 云端断网、超时、鉴权失败时，下一次录音可立即开始。

### 隐私

- 未授权与单次“仅本地”产生零外部请求。
- 自动测试证明出站对象无法包含音频、URL、路径、完整记录、密钥和剪贴板。
- 每次整理可查看本地隐私报告：发送了多少字、选择了哪些内部记录摘要。

### 内容质量

- 冻结 `v0.2-GS-01`：不少于 30 条用户真实中英粤混合记录；先人工拆成原子观点并保存版本。
- 每条样本逐项判定：零意义反转、零新增事实、零否定关系变化，任一出现即 P0 失败。
- 编号观点覆盖率 = 被至少一个要点覆盖的原子观点数 / 全部标注原子观点数，目标不低于 95%。
- 已显示的内部关联 100% 可解析；由用户对已显示链接逐条判定，相关链接数 / 已显示链接数目标不低于 90%。
- 所有推测连接均独立标注，不进入编号观点或已知关联。

### 界面与并发

- 新录音始终优先成为主岛。
- 迟到回调不能关闭新录音、切换主岛、串写其他记录或修改剪贴板。
- 手势均有可见按钮替代；Option-Space/Escape 保持可用；VoiceOver 能读出状态、操作和“推测”标签。
- 非刘海屏和外接屏仍能显示顶部岛及打开设置。

## 13. 明确不做

0.2 不做 Obsidian、Notion、外部文件夹扫描、知识图谱、向量数据库、聊天助手、多 Agent 运行时、自动执行待办、云端 ASR、音频上传、自动粘贴、全屏笔记编辑器、多设备同步、账号、团队、计费和 Provider 市场。

未来 Obsidian 接入的前置条件是：模型接口稳定、内部记录闭环稳定、权限和 Skill 操作可审计。0.2 不为它预建假入口。

## 14. 最终产品判断

0.2 的成功不由“模型更聪明”定义，而由三个可验证事实定义：

1. 整理永远没有伤害捕获；
2. 整理输出始终能回到原文证据；
3. 关联只在有真实内部记录时出现，推测永远不冒充事实。

只有这三点稳定后，TSB 才有资格从听写工具继续长成第二大脑。
